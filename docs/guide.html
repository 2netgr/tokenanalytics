1 Πώς λειτουργεί

Το TokenAnalytics διαβάζει τα τοπικά transcripts των coding agents σου, υπολογίζει tokens & κόστος, και τα δείχνει σε ένα dashboard. Δεν στέλνει τίποτα στο internet — όλα μένουν στο μηχάνημά σου.

~/.claude ~/.codex ~/.cursor ~/.gemini … (τα logs των agents σου) │ scan κάθε ~30s ▼ ┌──────────────┐ ┌─────────────────────────┐ ┌───────────────┐ │ Scanner │ ───► │ Durable store │ ───► │ Dashboard │ │ (διαβάζει │ │ ~/.tokenanalytics/ │ │ localhost:3000│ │ transcripts)│ │ history.db (μόνιμο) │ │ (backend │ └──────────────┘ └─────────────────────────┘ │ :8000) │ κρατάει ΟΛΟ το ιστορικό └───────────────┘ (δεν χάνεται στο 30ήμερο)

Τι παρακολουθεί

Agents
Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot, Qwen, Antigravity, OpenCode, Vibe, Grok
Μετρικές
input / output / cached / total tokens, κόστος (API-equiv), ανά agent & ανά μοντέλο, με χρονικά φίλτρα
Μόνιμο ιστορικό
το history.db δεν διαγράφει ποτέ — κρατάει τα δεδομένα όλων των εποχών, ακόμη κι όταν ο agent σβήνει τα δικά του logs
Subagents
τα delegated tokens μετριούνται ξεχωριστά — toggle «Include subagents» για να μπουν στο σύνολο
Cursor: τα transcripts του Cursor δεν εκθέτουν tokens — το TokenAnalytics τα εκτιμά από το κείμενο και τα τιμολογεί με τις τιμές του Composer (Composer 2.5: $0.50 in / $2.50 out / $0.20 cache-read ανά εκατ.). Εμφανίζονται ως «estimated».

2 Εγκατάσταση (macOS)

Με το έτοιμο installer (TokenAnalytics-macOS.zip) — δεν χρειάζεσαι terminal.

Προαπαιτούμενα

Node.js 18+, npm, git, Python 3.9+. Αν λείπει κάτι, ο installer σου το λέει με link. Γρήγορη εγκατάσταση:

xcode-select --install        # git + build tools
# Node & Python: από nodejs.org / python.org  ή  με Homebrew:
brew install node python

Βήματα

  1. Unzip το TokenAnalytics-macOS.zip.
  2. Δεξί κλικ στο install.command → Open. (Επειδή είναι unsigned, ο Gatekeeper θέλει right-click→Open την πρώτη φορά· αν μπλοκάρει: System Settings → Privacy & Security → Open Anyway.)
  3. Ο installer ελέγχει προαπαιτούμενα, κατεβάζει την τελευταία έκδοση στο ~/.tokenanalytics/app, στήνει LaunchAgent (auto-start στο login) και ξεκινά την εφαρμογή.
  4. Ανοίγει αυτόματα το dashboard στο http://localhost:3000. Έτοιμο.
Αναβάθμιση από παλιά εγκατάσταση: αν το μηχάνημα έχει παλιό ~/.tokentelemetry, ο installer μεταναστεύει αυτόματα τα δεδομένα στο ~/.tokenanalytics κρατώντας backup — δεν χάνεται τίποτα.

Απεγκατάσταση

Τρέξε το uninstall.command από το zip — αφαιρεί την εφαρμογή + τον LaunchAgent, αλλά κρατάει τα δεδομένα σου στο ~/.tokenanalytics.

3 Συγχρονισμός analytics από πολλά devices

Ο συγχρονισμός είναι αμφίδρομος: κάθε συσκευή στέλνει τα δικά της δεδομένα και κατεβάζει των άλλων, ώστε όλες οι συσκευές να δείχνουν τα πάντα.

Το μοντέλο (star)

┌─────────────────────┐ │ HUB (device 1) │ πάντα ανοιχτό, προσβάσιμο │ βλέπει ΟΛΑ τα data │ στο δίκτυο, με token └─────────────────────┘ ▲ push ▲ push │ pull ▼ │ pull ▼ ┌────────────┐ ┌────────────┐ │ device 2 │ │ device 3 │ peers: push τα δικά τους │ βλέπει ΟΛΑ │ │ βλέπει ΟΛΑ │ + pull του hub → mirror └────────────┘ └────────────┘

Διάλεξε ένα device ως hub (αυτό που είναι πάντα ανοιχτό). Όλα τα υπόλοιπα συνδέονται σε αυτό. Κάθε 60s γίνεται push + pull, και το (device_id, agent, id) εξασφαλίζει ότι δεν διπλασιάζεται ούτε χάνεται τίποτα.

Α) Στήσε τον hub (device 1)

Ο hub πρέπει να είναι προσβάσιμος στο δίκτυο με token. Ξεκίνα τον έτσι:

node bin/cli.js --host 0.0.0.0 --auth-token <ΤΟ-TOKEN-ΣΟΥ> \
    --allowed-origins <LAN-IP-του-hub>

Το token & το URL φαίνονται και στο dashboard του hub: Settings → Multi-device sync (ή «Connect a device»). Σε μόνιμη εγκατάσταση, ο LaunchAgent μπορεί να τα έχει ήδη ρυθμισμένα.

Β) Σύνδεσε κάθε άλλο device

  1. Εγκατέστησε κανονικά το TokenAnalytics στο device (Βήμα 2).
  2. Στο dashboard του → Settings → Multi-device sync → «Connect this device to your hub».
  3. Βάλε Hub URL (π.χ. http://192.168.1.20:8000) και το Access token.
  4. Πάτα Connect & sync. Από εκεί συγχρονίζεται αυτόματα.

Στον επιλογέα «Device» (Dashboard/Analytics) διαλέγεις: Local device, All devices (το συνολικό), ή μια συγκεκριμένη συσκευή.

Ιδιωτικότητα: ανταλλάσσονται μόνο summary rollups (tokens/κόστος/μοντέλο) — ποτέ prompts, κώδικας ή transcripts. Όλα μένουν μέσα στις δικές σου συσκευές, με token. Κανένα cloud ενδιάμεσο.

4 Σύνδεση μέσω internet (διαφορετικά δίκτυα)

Αν οι συσκευές δεν είναι στο ίδιο δίκτυο, ο ευκολότερος & ασφαλέστερος τρόπος είναι το Tailscale (δωρεάν mesh VPN).

  1. Εγκατέστησε Tailscale και στις δύο συσκευές, login με τον ίδιο λογαριασμό.
  2. Κάθε συσκευή παίρνει σταθερή ιδιωτική IP 100.x.x.x, προσβάσιμη από οπουδήποτε, end-to-end encrypted, χωρίς port-forwarding.
  3. Στο sync panel του peer, βάλε ως Hub URL την Tailscale IP του hub: http://100.x.x.x:8000 + το token.
Δουλεύει ακριβώς όπως στο LAN — αλλάζει μόνο η διεύθυνση. Αποφεύγεις να εκθέσεις τον hub δημόσια στο internet.

5 Ενημερώσεις

Όταν υπάρχει νέα έκδοση, εμφανίζεται μπάρα «Update available» στην κορυφή:

  • Update now — κατεβάζει μόνο του τα νέα αρχεία (git pull), κάνει restart και ξαναφορτώνει. Χωρίς terminal.
  • What's changed — popup με τις αλλαγές της έκδοσης.

6 Δεδομένα, backup & ασφάλεια

ΤιΠού / Πώς
Όλα τα δεδομένα~/.tokenanalytics/ (history.db + ρυθμίσεις). Διαγράφεται/μετακινείται ελεύθερα.
Μόνιμο ιστορικότο history.db δεν διαγράφει ποτέ captured rollups → κρατάς όλο το ιστορικό, όχι μόνο 30 μέρες
Telemetryκαμία — η εφαρμογή δεν στέλνει analytics σε κανέναν server
Sync ασφάλειαμόνο μέσα στις δικές σου συσκευές (LAN/Tailscale), token-protected, rollups-only
Tip: μην βάζεις τον φάκελο της εφαρμογής σε iCloud-synced Desktop/Documents — το iCloud μπορεί να «εκδιώξει» αρχεία σε cloud-only και να μπερδέψει git/venv. Προτίμησε π.χ. ~/Developer/.

7 Επίλυση προβλημάτων

«can't be opened» (Gatekeeper)
Δεξί κλικ → Open, ή System Settings → Privacy & Security → Open Anyway. Είναι unsigned.
Το peer δεν συνδέεται
Ο hub πρέπει να είναι ανοιχτός & προσβάσιμος (LAN IP ή Tailscale). Έλεγξε URL + token. Σε άλλο δίκτυο → Tailscale.
401 στο sync
Λάθος ή κενό token. Πάρε το σωστό από τον hub: Settings → Multi-device sync.
Πόρτα κατειλημμένη
node bin/cli.js --port 4000 --api-port 9000 για άλλες πόρτες.
Cursor δείχνει «estimated»
Σωστό — ο Cursor δεν εκθέτει tokens, οπότε εκτιμώνται από το κείμενο (τιμές Composer).
